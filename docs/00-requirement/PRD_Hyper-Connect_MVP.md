# 초기 앱 개발을 위한 상세 요구사항 명세서 (PRD)

**프로젝트명**: Hyper-Connect (MVP)
**작성일**: 2026-01-18
**버전**: 1.0

---

## 1. 목적 및 배경

### 비즈니스 목표
- 서울오토갤러리 및 대한민국 자동차 매매시장의 오프라인 자산을 디지털화
- 글로벌 바이어와 국내 자산가를 직접 연결
- 신뢰 기반의 검증 시스템을 통해 불필요한 대면 협상을 줄이고 거래 속도 향상

### 타겟 시장
- **국내**: 슈퍼카/하이퍼카 보유 자산가, 서울오토갤러리 위탁 판매자
- **글로벌**: 중동(UAE, 사우디), 북미, 일본 등 고급 차량 수입 바이어

---

## 2. 주요 사용자 및 유즈케이스

### 2.1 판매자 (Seller)
**플로우**: 차량 등록 → 전문 촬영 예약 → 실시간 오퍼 수령 → 정산 확인

**주요 니즈**:
- 고급 차량의 가치를 정확히 전달할 수 있는 상세 정보 입력
- 실시간 판매 진행 상황 모니터링
- 해외 바이어 접근 시 부가세 환급 혜택 확인

### 2.2 구매자 (Buyer)
**플로우**: 글로벌 매물 검색 → 4K 영상/평가서 확인 → 화상 검수 예약 → 구매 결정

**주요 니즈**:
- 신뢰할 수 있는 차량 정보 및 검증 리포트
- 원격으로 차량 상태 확인 (고해상도 미디어)
- 수출 가능 여부 및 가격 투명성

### 2.3 관리자 (Admin)
**플로우**: 매물 승인 → 검수 리포트 업로드 → 수출/금융 서류 관리 → 대시보드 모니터링

**주요 니즈**:
- 효율적인 매물 관리 시스템
- 검수 전문가와의 협업 도구
- 거래 진행 상황 실시간 추적

## 3. 핵심 기능 (Functional Requirements)

### F1. 하이엔드 자산 등록 ⭐ **[최우선 개발]**

**목적**: 단순 텍스트가 아닌 구조화된 데이터로 차량 자산의 가치를 정확히 전달

**필수 입력 항목**:
1. **기본 정보**
   - 제조사, 모델명, 연식, 주행거리
   - VIN(차대번호), 차량등록번호
   - 매칭넘버 여부 (원본 엔진/변속기 유지 여부)

2. **옵션표 (강제 입력)**
   - 체크박스 또는 구조화된 폼으로 제공
   - 예: 카본 브레이크, 리프트 시스템, 스포츠 배기 등
   - 브랜드별 주요 옵션 DB 구축 필요

3. **정비 이력 (이미지/PDF 업로드)**
   - 정비소 방문 기록
   - 소모품 교체 내역 (타이어, 브레이크 패드 등)
   - 최대 파일 크기: 10MB/파일, 총 50MB

4. **소모품 상태 입력**
   - 타이어: 잔량(%), 교체 일자
   - 브레이크: 패드 두께(mm), 디스크 상태
   - 엔진오일: 교체 일자, 주행거리

5. **미디어 자료**
   - 외관/내부 사진: 최소 20장
   - 4K 영상: 선택 사항 (전문 촬영 예약 시 자동 등록)
   - 엔진 사운드 클립

**비즈니스 규칙**:
- 필수 항목 미입력 시 등록 불가
- 관리자 승인 전까지 비공개 상태 유지
- 검수 리포트 업로드 전까지 "검증 대기" 배지 노출

---

### F2. 글로벌 다국어 인터페이스

**지원 언어**: 한국어, 영어, 아랍어

**기능**:
- 언어 선택 시 모든 UI 텍스트 변환
- 환율 실시간 변환 (KRW ↔ USD)
- 차량 설명란은 다국어 별도 입력 필드 제공

**기술 요구사항**:
- i18n 라이브러리 활용 (React: react-i18next, Vue: vue-i18n 등)
- 환율 API 연동 (예: ExchangeRate-API, Fixer.io)
- RTL(Right-to-Left) 레이아웃 지원 (아랍어)

---

### F3. 디지털 검수 리포트

**내용**:
- 전문가가 작성한 120가지 항목 점검표
- 사고 유무 판독서 (CarFax 스타일)
- 외관/엔진/하부 상세 체크리스트

**시각화**:
- 항목별 그래프 (Good/Fair/Poor)
- 차량 다이어그램에 손상 부위 표시
- 평가 점수: S/A/B/C/D 등급

**권한**:
- 일반 유저: 읽기 전용
- 관리자/검수자: 작성 및 수정 가능

---

### F4. 실시간 오퍼 시스템

**플로우**:
1. 바이어가 희망 가격 제안 (Offer)
2. 판매자에게 푸시 알림 발송
3. 자동으로 1:1 채팅방 개설
4. 판매자는 수락/거절/재제안 가능

**기술 요구사항**:
- WebSocket 또는 Firebase Realtime Database
- 푸시 알림: FCM(Firebase Cloud Messaging)

## 4. 비기능 요구사항 (Non-Functional Requirements)

### 4.1 보안

**필수 구현**:
- 2단계 인증 (2FA): 고액 거래 특성상 필수
- SSL/TLS 암호화 통신
- 개인정보 마스킹 처리 (차량등록증, 신분증 등)

**권장 사항**:
- AWS KMS를 통한 데이터 암호화
- OWASP Top 10 보안 취약점 점검

---

### 4.2 미디어 처리

**요구사항**:
- 4K 영상 스트리밍 최적화
- CDN 활용 (AWS CloudFront, Cloudflare)
- 이미지 자동 압축 및 리사이징 (Sharp, ImageMagick)

**목표 성능**:
- 이미지 로딩 시간: 1초 이내
- 4K 영상 버퍼링: 최소화 (Adaptive Bitrate Streaming)

---

### 4.3 성능

| 메트릭 | 목표 |
|--------|------|
| 페이지 로딩 시간 | 3초 이내 |
| API 응답 시간 | 200ms 이내 |
| 동시 접속자 | 1,000명 지원 |

---

### 4.4 호환성

**플랫폼**:
- Web: Chrome, Safari, Firefox (최신 2개 버전)
- Mobile: iOS 14+, Android 10+
- 반응형 디자인 (Responsive)
