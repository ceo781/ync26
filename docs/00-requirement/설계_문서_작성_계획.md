## 개요

F1. 하이엔드 자산 등록 기능을 중심으로 MVP 설계 문서를 작성합니다.

**작업 방식**: 문서 우선 (Documentation First)
- 코드 작성 전에 명확한 설계서를 작성
- AI가 이해할 수 있는 구조화된 문서 형식
- 작은 단위로 분할하여 검증

---

### 2. 데이터베이스 스키마 설계서
**파일 경로**: `docs/01-development/02_데이터베이스_스키마.md`

**포함 내용**:
- ERD (Entity Relationship Diagram)
- 테이블 정의
  - `users`: 사용자 정보
  - `vehicles`: 차량 기본 정보
  - `vehicle_options`: 차량 옵션 (다대다 관계)
  - `maintenance_records`: 정비 이력
  - `consumable_status`: 소모품 상태
  - `media_files`: 미디어 파일 메타데이터
  - `inspection_reports`: 검수 리포트 (P1)
- 필드 정의 (타입, 제약조건, 인덱스)
- 관계 설정 (Foreign Key)

**예상 작업량**: 2일

---

### 3. API 명세서
**파일 경로**: `docs/01-development/03_API_명세서.md`

**포함 내용**:
- RESTful API 엔드포인트 목록
- F1 기능 관련 주요 API:
  - `POST /api/vehicles` - 차량 등록
  - `PUT /api/vehicles/:id` - 차량 정보 수정
  - `POST /api/vehicles/:id/media` - 미디어 업로드
  - `POST /api/vehicles/:id/maintenance` - 정비 이력 추가
  - `GET /api/vehicles` - 차량 목록 조회
  - `GET /api/vehicles/:id` - 차량 상세 조회
  - `POST /api/admin/vehicles/:id/approve` - 관리자 승인
- 요청/응답 스키마 (JSON)
- 인증 방식 (JWT Bearer Token)
- 에러 코드 정의

**예상 작업량**: 2일

---

### 4. 페이지 구조 설계서

## 기술 스택 사전 조사 필요 사항

설계 문서 작성 전에 다음 기술 스택을 선정해야 합니다:

### Frontend
- [ ] React/Next.js vs Vue/Nuxt.js
- [ ] 상태 관리: Redux vs Zustand vs Recoil
- [ ] UI 라이브러리: Tailwind + Shadcn/ui vs Material-UI
- [ ] 폼 라이브러리: React Hook Form vs Formik

### Backend
- [ ] Node.js (NestJS) vs Python (FastAPI)
- [ ] ORM: Prisma vs TypeORM vs Sequelize

### Database
- [ ] PostgreSQL (확정) + Redis (캐싱)

### Storage/CDN
- [ ] AWS S3 + CloudFront vs Cloudflare R2

### 권장 스택 (빠른 개발 우선)**:
- **Frontend**: Next.js 14 (App Router) + TypeScript + Tailwind + Shadcn/ui
- **Backend**: NestJS + Prisma + PostgreSQL
- **Storage**: AWS S3 + CloudFront
- **Auth**: NextAuth.js (JWT)
- **Deployment**: Vercel (Frontend) + AWS EC2/ECS (Backend)
